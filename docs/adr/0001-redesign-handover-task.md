# ADR 0001：将空手接近改为安全物体交接任务

## 状态

已接受

## 背景

旧任务把机器人底座放在人体伸手方向附近，并从人体手部仍在运动时开始高频 IK。夹爪全程打开，任务成功只表示 TCP 到达手部附近的空间点，不表示发生了抓取或物体交接。

当前人体是 HY-Motion 驱动的运动学代理，不会因为机器人接触产生真实人体动力学反馈。因此需要先定义一个可复现的运动学交接协议，再逐步替换为完整动力学交接。

## 决策

任务改为以下阶段：

```text
RESET
-> SCENE_LAYOUT_CHECK
-> HUMAN_WALK
-> HUMAN_REACH
-> HUMAN_HAND_STABLE
-> ROBOT_PREGRASP_APPROACH
-> ROBOT_SLOW_APPROACH
-> GRIPPER_CLOSE
-> GRASP_VERIFY
-> HUMAN_RELEASE
-> ROBOT_RETREAT
-> SUCCESS
```

具体约束：

1. 机器人位于人体侧前方，初始布局由人体代理与机器人代理的实际距离检查通过后才能开始。
2. 原始 HY-Motion 动作不修改；任务回放在末尾增加静止保持段，为预抓取、闭合和验证留出时间。
3. 人体手部稳定前，机器人只保持观察姿态，不追踪移动中的手腕。
4. 机器人先到预抓取位，再以有限 TCP 速度接近物体；位置 IK 不能替代速度限制。
5. 物体在交接前跟随人体手部，夹爪闭合后通过接触和相对位姿稳定性验证抓取，验证通过才转移控制权。
6. 机器人撤回后，物体必须继续稳定跟随机器人；掉落或碰撞均判定失败。
7. 任务成功还必须满足人体代理与机器人代理的最小 AABB 距离门槛；仅有
   `collision_steps == 0` 不足以证明安全，因为离散接触统计可能漏掉几何贴碰。

## 取舍

本决策不宣称人体已经具备真实接触动力学。运动学人体与物体绑定是当前阶段的可重复基线，能够隔离机器人接近、夹爪闭合、控制权转移和撤回问题。后续接入人体动力学时，应保留同一状态机和验收指标。

## 影响

旧的 `walking_approach_safe_hand_interaction` 结果只能作为空手接近基线，不能作为物体交接成功结果。新的报告必须同时记录布局距离、TCP 速度、抓取验证、控制权转移和撤回结果。

## 当前实测边界

在 2026-09-22 的 CPU smoke test 中，旧版 `16+24` 秒预抓取/慢速接近时序明显长于
实际末端运动需求，容易让观察者误以为机械臂停止。当前默认时序改为 `16+14` 秒，
仍保留 `--max-joint-speed 0.35` 和 `--max-tcp-speed 0.10` 的限速；过短的
`--seconds 5` 仍会稳定地以 `FAILED_GRASP` 结束，因为它只执行到预抓取开始。
长时序版本已验证抓取、控制权转移和撤回，
但固定底座布局仍需继续优化 AABB 安全余量；因此抓取成功不能直接等同于整体安全成功。
