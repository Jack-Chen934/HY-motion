# 人机交互基准任务设计

## 1. 任务名称

**Walking Object Handover and Safe Transfer**

中文名称：**人行走递物、机器人安全交接任务**。

这是当前默认的整体 HRI 验证任务。它直接使用已有 HY-Motion 动作：

> A person walks forward, turns to the side, reaches forward with one hand, and pauses.

任务显式加入可见交接物体，并把动作播放、安全接近、抓取验证和控制权转移分阶段验收。

## 2. 验证目标

该任务一次性验证以下链路：

```text
HY-Motion poses/trans
        -> WoodenMesh 完整人体显示
        -> 22 关节人体碰撞代理
        -> Genesis 同步回放
        -> 机器人加载与控制
        -> 人体接近检测
        -> 机器人安全接近
        -> 预抓取、慢速接近、夹爪闭合
        -> 抓取验证、控制权转移和撤回
        -> 碰撞和连续性评估
```

当前目标是验证可重复的运动学交接基线，不是训练策略，也不是人体动力学真实性验收。

## 3. 场景和坐标约定

采用 Genesis Z-up 坐标，单位为米，时间步长为 0.01 s。

- 人体动作使用当前基准文件：`motions/prepared/final_full_cooperation_seed2026.npz`。
- 人体根部初始位置由任务配置给出，默认将动作放置到机器人工作区前方。
- 动作本身沿 Genesis 负 Y 方向前进；当前片段骨盆从约 `y=0` 移动到 `y=-2.18`。
- 人体视觉层使用 WoodenMesh。
- 人体碰撞层使用 `assets/human_22ball.xml`。
- 机器人使用 R1 Pro URDF，但任务适配器只读取机器人项目的场景/控制接口，不修改该项目。
- 网格和碰撞代理必须使用同一个人体根部变换和同一个时间采样。

建议的初始布局是：

```text
人体：动作路径的起点位于工作区前方
机器人：位于人体路径侧前方，而不是正面堵住路径
交互区：人体终点左手腕附近，距离人体躯干约 0.6~0.8 m
机器人准备位：交互区外侧，末端与左手腕目标保持约 0.08~0.15 m
```

具体世界坐标在首次同场景接入时通过 viewer 校准，不写死在动作转换器中。

## 4. 状态机

```text
RESET
  -> HUMAN_WALK
  -> HUMAN_TURN_REACH
  -> HUMAN_PAUSE_DETECTED
  -> ROBOT_APPROACH
  -> INTERACTION_READY
  -> HOLD
  -> SUCCESS
```

任意阶段都可以进入 `SAFETY_ABORT`：

```text
最小安全距离不足
发生实体碰撞
人体或机器人发生非预期位姿跳变
机器人 IK 不可达
viewer/仿真步停止
```

### 阶段定义

| 阶段 | 人体 | 机器人 | 主要判定 |
|---|---|---|---|
| `RESET` | 根部和网格加载到首帧 | R1 Pro 加载并稳定 | 所有实体存在，初始碰撞为 0 |
| `HUMAN_WALK` | 播放动作前段 | 保持安全观察位 | 人体网格和代理同步 |
| `HUMAN_TURN_REACH` | 播放转身和左手伸出 | 可开始底盘接近 | 不得进入人体安全半径 |
| `HUMAN_PAUSE_DETECTED` | 左手腕进入低速窗口 | 锁定交互目标 | 低速持续时间满足阈值 |
| `ROBOT_APPROACH` | 继续保持动作 | 底盘和左臂到准备位 | 导航误差和末端误差合格 |
| `INTERACTION_READY` | 左手停在目标附近 | 末端保持安全交互位 | 距离与朝向合格 |
| `HOLD` | 停顿结束前不要求新动作 | 保持 0.5 s | 无碰撞、无明显漂移 |
| `SUCCESS` | 动作回放结束 | 安全退出或保持 | 所有指标通过 |

## 5. 当前动作的交互窗口

根据当前 150 帧、30 FPS 片段的实际关键点：

- 左手腕末段相对骨盆位移约为 `(-0.234, -0.660, 0.172) m`；
- 左手腕位于人体前进末端附近，适合作为交互端点；
- 最后约 1.1 s（约 `3.9~5.0 s`）左手腕速度连续低于 `0.12 m/s`，可作为第一版暂停窗口；
- 右手腕没有同样清晰的前伸目标，因此第一版不使用右手。

第一版检测器建议：

```text
hand = L_Wrist
relative_speed_threshold = 0.12 m/s
minimum_pause_duration = 0.50 s
reach_window = clip_time >= 3.4 s
detected_pause_window = 3.9 s .. 5.0 s
```

这些阈值用于检测，不修改原始动作。后续应从真实轨迹统计中自动估计窗口，而不是永久依赖固定秒数。

## 6. 交互目标定义

目标点不应直接使用网格顶点。使用人体代理或动作关键点定义目标：

```text
hand_target(t) = left_wrist_world(t)
approach_target = hand_target - approach_direction * 0.10 m
```

`approach_direction` 取人体左手前伸方向的水平归一化向量；当方向退化时，使用人体面向方向。机器人末端只到达 `approach_target`，不直接追踪或穿过手腕。

第一版不执行真实握手或物体抓取，只验证机器人能否安全到达手部附近并保持。如果这一步稳定，再加入“人递物—机器人夹取”的第二个任务。

## 7. 验收指标

### A. 动作与网格

| 指标 | 第一版要求 |
|---|---:|
| 动作完成率 | 100% |
| 网格顶点更新错误 | 0 |
| 网格顶点数量变化 | 0 |
| 人体代理父子骨长误差 | `< 1e-4 m` |
| 网格/代理根部同步误差 | `< 1e-4 m` |
| 非预期人体根部跳变 | `<= 0.03 m/step` |

### B. 人机安全

| 指标 | 第一版要求 |
|---|---:|
| 人体代理与机器人碰撞次数 | 0 |
| 最小代理间距 | `>= 0.25 m` |
| 机器人进入人体安全禁区 | 0 次 |
| 机器人末端到手腕目标距离 | `<= 0.10 m` |
| 交互准备位保持时间 | `>= 0.50 s` |

这里的 `0.25 m` 是保守的第一版个人空间阈值，不代表最终人体安全标准；应根据机器人尺寸、速度和任务需求重新标定。

### C. 机器人执行

| 指标 | 第一版要求 |
|---|---:|
| 底盘目标位置误差 | `<= 0.08 m` |
| 末端 IK 位置误差 | `<= 0.05 m` |
| 目标不可达次数 | 0 |
| 控制器超时 | 0 |
| 任务结束时机器人状态 | 可控停止 |

## 9. 实施顺序

### 阶段 A：当前独立仓库完成

1. 保持现有完整网格 + MJCF 代理回放不变。
2. 加入人体动作阶段检测器和关键点日志。
3. 实现离线“交互窗口、手腕目标、安全半径”计算。
4. 使用固定机器人占位点验证指标和失败分支。

### 阶段 B：同场景接入

1. 新建独立适配脚本，读取 R1 Pro URDF 的绝对路径。
2. 在同一 Genesis scene 中加入 R1 Pro、人体视觉层和 MJCF 代理。
3. 先关闭人体动力学，只使用已验证的人体运动学回放。
4. 只做机器人观察位和准备位，不做接触、不做夹取。
5. 通过 viewer 检查三层是否重合：网格、人体代理、机器人碰撞几何。

### 阶段 C：交互响应与交接

1. 使用人体左手腕进入窗口作为事件。
2. 机器人底盘移动到安全准备位。
3. 左臂 IK 到 `approach_target`。
4. 先到预抓取位，再以限速接近物体并闭合夹爪。
5. 验证 TCP—物体相对距离和稳定性，转移物体控制权后撤回。
6. 重复多个 seed 和不同人体初始位置。

### 阶段 D：动力学升级

当前 `handover` 是运动学人体和分阶段物体控制基线。下一步才将物体改为动态刚体，
加入夹爪接触约束、人体 PD/扭矩控制和真实释放响应；不把当前基线误称为完整动力学交接。

## 10. 当前实际验证结果

已使用 `run_hri_walking_approach.py --profile handover` 完成当前动作的 Genesis
交接回放，报告为 `reports/handover_final_redesign.json`，结果如下：

| 指标 | 实际结果 |
|---|---:|
| 任务状态 | `success` |
| WoodenMesh 顶点 / 三角面 | `24256 / 48396` |
| 预抓取 / 慢速接近 | `16 s / 14 s` |
| TCP—物体最小距离 | 约 `3.9e-8 m` |
| 抓取、控制权转移、撤回 | 全部成功 |
| 交接前最小 AABB 距离 | `0.0609 m` |
| 实际碰撞步数 | `0` |

当前物体在交接前跟随人体手部，抓取验证后跟随机器人 TCP；这是可重复的控制权
转移基线，不是动态接触证明。

当前 `min_human_robot_aabb_distance_m=0` 只表示某些碰撞几何的轴对齐包围盒
发生重叠。AABB 是 broad-phase 保守指标，不是表面距离；第一版的安全验收使用
Genesis 实际接触查询、代理碰撞步数和末端误差。后续若需要严格的人体安全距离，
应增加针对人体代理与机器人碰撞几何的窄相位距离接口。

## 11. 下一步

当前默认实现已经完成“人体运动学回放 + 机器人受限速度交接”的成功路径验证。
下一步按
以下顺序推进：

1. 使用 `--viewer` 检查完整网格、22 关节代理和 R1 Pro 碰撞几何在关键帧的空间重合；
2. 对多个动作 seed、人体初始位置和机器人初始位置重复任务；
3. 增加窄相位人体—机器人距离和速度相关安全约束；
4. 将运动学物体控制替换为动态刚体和夹爪接触约束；
5. 最后再接入协作控制、观测空间和训练接口。

## 12. 当前边界和风险

- 当前人体仍是运动学回放，不是受重力和接触力控制的动力学人体。
- 完整网格是视觉层，不参与碰撞；安全判定依赖 MJCF 代理。
- WoodenMesh 和 22 关节代理的关节表示不同，需要持续监测网格—代理局部偏差。
- R1 Pro 现有场景的桌子、柜子和物体任务可以复用其控制能力，但不能把其代码直接复制进本仓库后再称为隔离。
- 当前任务的“交互成功”是可重复的运动学物体交接，不等同于真实人体接触动力学。

## 13. 最终判定

第一版任务只有在以下条件同时满足时才算通过：

```text
HY-Motion 动作完整播放
AND 完整网格无拓扑/更新错误
AND 人体代理连续且无异常跳变
AND 机器人成功到达预抓取位和抓取位
AND 交接前满足人体—机器人安全距离
AND 抓取验证、控制权转移和撤回成功
AND 代理碰撞次数 = 0
AND 交互窗口内末端误差 <= 0.10 m
AND 准备位保持 >= 0.50 s
AND 任务结束时机器人可控停止
```
