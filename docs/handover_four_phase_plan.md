# 人机交接四阶段实施计划

本文档定义“HY-Motion 人体动作 + Genesis 人体模型 + R1 Pro 机械臂 + 交接物体”的完整升级路线。实施顺序固定为四个阶段，前一阶段的验收通过后才进入下一阶段。

## 总体原则

- 不修改 `gaze_vr_isaaclab` 的业务代码，只读取其中的 R1 Pro 资产。
- 人体视觉网格、人体碰撞代理和交接物体分层建模。
- 先解决几何、姿态和状态机，再引入动力学；不使用“物体跟随 TCP”冒充真实抓取。
- 每个阶段都必须同时有可视化检查、结构化报告和自动化验收指标。
- 任何阶段出现关节脱离、物体跳变、穿模或接触判定与视觉不一致，都停止向下一阶段推进。

## 阶段一：掌心几何与物体视觉定位

### 目标

把物体从“腕部附近的点”改为“位于拇指和食指之间、朝向与掌面一致的物体”，先解决用户当前看到的物体挂在手腕上的问题。

### 实施内容

1. 使用 WoodenMesh 的左手关键点构造掌心局部坐标系：
   - 原点参考：左手腕、食指根部、中指根部、无名指根部、小指根部、拇指根部。
   - X 轴：拇指根部到食指根部的夹持方向。
   - Y 轴：手腕指向掌根/手指的方向。
   - Z 轴：由 X、Y 叉乘得到的掌面法向。
2. 物体中心放在拇指根部和食指根部的中点，并进一步向掌心核心做比例偏移。
3. 物体尺寸从 `0.08 m` 降至约 `0.04 m`，避免立方体自身覆盖腕部。
4. 物体姿态随掌面旋转，不再保持世界坐标轴对齐。
5. 增加诊断指标：
   - 物体到腕部距离；
   - 物体到食指根部距离；
   - 物体到拇指根部距离；
   - 物体到掌心质心距离；
   - 拇指—食指间距；
   - 物体位置和姿态的采样轨迹。

### 验收标准

- 物体中心不再落在腕部到掌根的单一线段上。
- 可视化中物体位于掌心区域，而非覆盖前臂末端。
- 物体姿态与手掌方向一致。
- 物体在动作播放过程中没有突然跳变。
- 阶段一不声称“抓取成功”，因为此时物体仍是运动学跟随。

### 当前状态

已开始实施。当前脚本使用掌心局部坐标系和拇指—食指夹持中心，保留旧位置函数作为兼容接口。待完成测试和回放验收后关闭本阶段。

## 阶段二：夹爪几何、姿态和双指抓取准备

### 目标

让机器人末端真正对准夹爪的有效抓取区域，而不是只把 TCP 中心移动到物体中心。

### 实施内容

1. 从 R1 Pro URDF 读取并标定：
   - `left_gripper_link`；
   - 左右手指链接；
   - 两个手指的碰撞盒；
   - 手指有效接触面和接触法向。
2. 建立夹爪坐标系：
   - 夹持轴；
   - 开合轴；
   - 物体插入方向；
   - TCP 到物体中心的固定偏移。
3. 将预抓取目标和最终抓取目标分离：
   - 预抓取位位于物体外侧；
   - 最终抓取位保证物体中心位于两指中间；
   - 夹爪姿态必须与物体姿态匹配。
4. IK 同时约束位置和姿态，不再使用只约束位置的配置。
5. 夹爪闭合速度和机械臂末端速度分别限速。
6. 增加抓取前诊断：
   - 物体中心到左右指尖距离；
   - 两指中点到物体中心距离；
   - 夹爪开口宽度；
   - 物体是否位于夹爪开口内部；
   - 夹爪姿态误差。

### 验收标准

- 左右手指分别位于物体两侧。
- 物体中心位于夹爪开口内，不能只接近 `left_gripper_link` 的 TCP。
- 夹爪闭合前后无明显穿模。
- 机器人接近速度、闭合速度和撤回速度均在配置上限内。
- 阶段二可以证明“几何上具备抓取条件”，但还不等于物理抓取成功。

## 阶段三：动态物体、接触和控制权转移

### 目标

把当前的运动学物体改为真实动态刚体，建立从人体到机器人夹爪的控制权转移。

### 实施内容

1. 交接物体使用 `fixed=False`，具有质量、惯量、摩擦和碰撞几何。
2. 人体侧采用明确的暂时保持机制：
   - 交接前物体跟随掌心或连接到人体手部代理；
   - 该机制必须可删除，不能通过每帧无条件 `set_pos()` 隐藏失败。
3. 机器人接近后执行状态机：

   ```text
   HUMAN_HOLD
       -> ROBOT_PREGRASP
       -> ROBOT_CONTACT
       -> GRIPPER_CLOSE
       -> DUAL_FINGER_CONTACT
       -> HUMAN_RELEASE
       -> ROBOT_WELD
       -> ROBOT_RETREAT
   ```

4. 双指接触持续满足阈值后，删除人体侧保持约束。
5. 使用 Genesis 的 weld/equality 约束把物体连接到夹爪链接，或者在明确验证过的版本中使用接触摩擦抓取。
6. 撤回阶段不再调用 `object_entity.set_pos(tcp_position(...))`；物体必须由动力学约束自然跟随。
7. 必要时增加次级安全约束，防止物体在约束建立瞬间掉落。

### 验收标准

```text
dynamic_after_grasp == true
robot_contact_steps > 0
left_finger_contact == true
right_finger_contact == true
human_object_contact_after_transfer == 0
relative_object_gripper_pose_stable == true
```

抓取后撤回期间，物体与夹爪的相对位置误差建议不超过 `5 mm`，并且连续保持至少 `0.5 s`。如果机器人撤回而物体不动、掉落或穿过手指，阶段三失败。

## 阶段四：完整人机协作任务与稳定性验证

### 目标

把真实交接接入完整人机协作任务，用于研究人体动作、机器人行为和物体交接的整体效果。

### 实施内容

1. 保留 HY-Motion 生成的人体动作作为人体行为输入。
2. 设计合理的空间布局：
   - 人与机器人保持足够初始距离；
   - 人伸手区域位于机器人工作空间内；
   - 机器人手臂不会穿过人体主体；
   - 物体交接点不与人体网格或碰撞代理重叠。
3. 将机器人控制划分为观察、接近、预抓取、抓取、撤回和放置阶段。
4. 增加失败恢复：
   - IK 无解；
   - 物体未进入夹爪；
   - 单指接触；
   - 接触后物体滑落；
   - 人体突然移动；
   - 人体—机器人安全距离不足。
5. 执行多次实验：
   - 不同 HY-Motion seed；
   - 不同人体初始位置和朝向；
   - 不同物体尺寸、质量和摩擦；
   - 不同机器人接近速度。
6. 记录成功率、抓取延迟、物体相对位姿误差、碰撞次数、IK 失败率、动作流畅度和实时性能。

### 最终验收标准

- 多次实验中任务成功率达到预设目标。
- 无关节脱离、明显穿模和物体传送。
- 人体网格、碰撞代理和动作关键点保持一致。
- 机器人抓取和撤回由真实动力学状态支持。
- 报告能够区分运动学回放成功、几何抓取成功和动力学交接成功。
